**Location:** `docs/02-data-model/Canonical-Data-Model.md`

# Purpose

This document defines the canonical entities that make up LifePilot.

Every piece of information stored by the application must ultimately belong to one of these entities.

No feature should introduce a new storage concept without updating this document.

This document is the foundation for:

* Database Schema
* AI Retrieval
* Search
* Timeline
* Object Views
* OCR
* Relationships
* Tasks

---

# Entity Hierarchy

```
Profile
│
├── Domains
│
├── Objects
│     │
│     ├── Documents
│     ├── Events
│     ├── Tasks
│     ├── Metadata  (including ai_context field)
│     └── Relationships
│
├── Goals
│     └── Tasks
│
├── Conversations
│     └── ChatMessages
│
└── Timeline
```

Everything in the application ultimately belongs to a Profile.

# 4. Metadata

Metadata stores structured information about an Object.

Metadata is extensible and schema-driven.

## MetadataEntry Fields

```
metadataId
objectId
fieldId
fieldType
value
version
confidence
source
verificationStatus    ← VerificationStatus enum (UNVERIFIED, VERIFIED, REJECTED)
updatedAt
```

## VerificationStatus

Every metadata entry carries a `verificationStatus` indicating whether a human has reviewed it:

```
UNVERIFIED   — default; AI-extracted or auto-generated, not yet reviewed
VERIFIED     — user explicitly accepted this value
REJECTED     — user explicitly rejected this value
```

Metadata written by the user directly is stored as `VERIFIED`. Metadata proposed by AI is stored as `UNVERIFIED` until the user acts on the proposal.

## Special Field: ai_context

The field `fieldId = "ai_context"` stores an `AiObjectContext` serialised as JSON in the `value` column. It is displayed in Object Detail as a distinct "AI Context" card, separate from the regular Details list. It is never rendered in the schema-driven Details list.

## Example Metadata

Passport:

```
passportNumber, country, issueDate, expiryDate, issuingAuthority
```

Vehicle:

```
registrationNumber, manufacturer, model, purchaseDate, insuranceExpiry
```

Job:

```
company, role, joiningDate, salary, employmentType
```

Metadata should always be type-specific.

## Status

```

## TaskSource

```

RECURRING     — generated by a recurring rule

# 11. Goal

Goals represent multi-step outcomes the user is working toward.

Goals contain suggested tasks and may be linked to one or more Objects.

## Goal Fields

```
id
profileId
title
description

status          ← GoalStatus enum

createdAt
updatedAt
```

## GoalStatus

```
DRAFT       — created but not yet active
PROPOSED    — suggested by AI, awaiting user acceptance
ACTIVE      — user is actively working toward this goal
COMPLETED   — all required tasks done
ARCHIVED    — no longer relevant, retained for history
CANCELLED   — explicitly abandoned
```

# 12. AI Engine Models

These models are not persisted directly as first-class entities but underpin the AI pipeline.

## AiObjectContext

Structured AI analysis stored per object in the `ai_context` metadata field (as JSON). See Metadata-System.md for storage details.

```
summary           — one-paragraph description of the object's current state
importantFacts    — bullet list of key facts the AI extracted
currentSituation  — what is happening now (e.g., "Expires in 45 days")
suggestions       — recommended next actions
lastUpdated       — when this context was last generated
confidence        — 0.0–1.0 confidence score
```

## ObjectSnapshot

The per-object view produced by `ObjectReasoner` and consumed by `PromptBuilder`.

```
objectId, title, objectType, domain, status
metadata            — all MetadataEntry values for this object
aiContext           — parsed AiObjectContext if present
pendingTaskCount
documentCount
relevanceScore      — keyword score assigned by RetrievalEngine
```

## RetrievalContext

The complete input to `PromptBuilder`. Built by `RetrievalEngine`.

```
profileId, profileName
relevantSnapshots       — up to 5 ObjectSnapshots
totalObjectCount
allObjectIndex          — lightweight title/type/domain index for all objects
allObjectMetadata
pendingTasks            — up to 10 pending tasks for the profile
upcomingReminders       — up to 10 reminders in the next 30 days
```

# Entity Rules

The following rules are mandatory.

* Every Object belongs to exactly one Profile.
* Every Document belongs to exactly one Object.
* Every Event belongs to exactly one Object.
* Every Task belongs to exactly one Object (and optionally one Goal).
* Every Reminder belongs to exactly one Object.
* Every Relationship connects exactly two Objects.
* Every Goal belongs to exactly one Profile.
* Timeline entries are generated, never manually edited.
* Metadata is attached to Objects, never Documents.
* The `ai_context` metadata field is reserved for `AiObjectContext` JSON.

---

# Design Philosophy

LifePilot should never introduce additional storage concepts unless absolutely necessary.

Every feature should reduce to combinations of:

* Profiles
* Domains
* Objects
* Metadata
* Documents
* Events
* Tasks
* Goals
* Relationships
* Reminders

If a proposed feature cannot be expressed using these entities, reconsider the design before implementation.
